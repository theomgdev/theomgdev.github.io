Privacy Policy

Hermes Agent · last updated 3 October 2026

This policy describes how the application Hermes Agent accesses, uses, stores and shares Google user data. Hermes Agent is a personal, single-user assistant run by Cahit Karahan on his own computer. The only Google Account it is authorized against is the operator's own account, cksoftwaresystems@gmail.com.

Who is the data subject

The operator and the user are the same person. This application has no other users and does not accept sign-ups. It therefore processes only the operator's own Google data, at the operator's own request.

What data is accessed, and why

  • Gmail messages and metadata (gmail.readonly, gmail.modify, gmail.send) — to list, read, search, label, archive, draft, send and reply to mail in the operator's own mailbox when the operator asks the assistant to do so.
  • Calendar events (calendar) — to read the operator's schedule for daily briefings and to create, modify or delete the operator's own events on request.
  • Drive files, Docs and Sheets (drive, documents, spreadsheets) — to read, create and edit the operator's own files as part of document and data automation tasks.
  • Contacts (contacts.readonly) — to resolve a contact's email address or phone number when the operator asks the assistant to contact someone.

How the data is used

Data is fetched on demand, used to carry out the task the operator requested in that session, and then discarded from working memory when the session ends. Message and document contents are processed only to produce the output the operator asked for — for example a summary of the inbox, a drafted reply, or an edited spreadsheet.

How the data is stored

  • OAuth tokens are stored on the operator's local disk, in %LOCALAPPDATA%\hermes\google_token.json, readable only by the operator's own Windows user account. They are transmitted only to Google's OAuth and API endpoints.
  • Google user data is not copied into any database or cloud store. It is held in process memory for the duration of a task. Where the operator explicitly asks for a file to be saved (for example "export this to a spreadsheet"), the resulting file is written to the operator's own local disk.
  • No analytics, telemetry or tracking of Google user data takes place.

How the data is shared

Google user data is not sold, rented, traded or shared with any third party for advertising, marketing, credit assessment, or model training purposes.

One disclosure case exists and is stated plainly: Hermes Agent is driven by a large language model, so the text of a task — which may include the content of a mail message, calendar entry or document the operator asked about — is sent to the model provider in order to generate the response. The operator configures which provider is used. No other recipient receives Google user data.

Limited use

This application's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Specifically, Google user data is used only to provide and improve the features the operator requested, is not transferred to others except as required to operate those features, is not used for advertising, and is not read by any human other than the operator.

Retention and deletion

No long-term copy of Google user data is retained. Authorization can be withdrawn at any time by the operator from Google Account permissions, or locally by deleting the stored token file, which immediately and permanently ends all access.

Changes

If the way this application uses Google user data changes, this page is updated with a new revision date before the change takes effect.
